## 1. Document inventory: "Add more documents…" button

**Why:** clients often send documents later. I need to add them to a run that's already open instead of starting over.

**Where:** on the Document inventory, in the left corner of the bottom row, on the same row as **Send to AI tab**
(`templates\inventory.html`, the `invadd` row). Label: **Add more documents…**

**What it does:**
- Opens the browser's file window (several files at once). Adding a folder as well would be nice if it's easy.
- The new documents are read like the first ones: the stuck-PDF guard (`web\probe.js`) runs on the new PDFs, the parsers
  read them, and they appear in the inventory with their type, amounts and links (the PDF opens in a Chrome tab like the others).
- **Everything is recalculated:** the Income and Deduction Summary, the form tabs, and anything else that depends on the documents.
- **Nothing I've done is lost:** ticks, corrected amounts, amounts typed for unread documents, AI ticks, K-1 work, and
  Schedule C / E. The existing documents keep their state exactly.
- **Duplicates:** a file that's already in the list (same file) isn't added twice. Show a short note naming it.
- The work in progress is saved after the add, as after any other change, and the new documents are in it when it's reopened.

**Watch out:**
- `copyFiles` in `web\worker.js` wipes `/client` and `/work` on every run. Adding must not wipe the documents already there.
- One possible approach: the existing open-saved-work path (`core\runcheck.py` `open_work` / `put_back_work`) already
  restores corrections onto a fresh run by fingerprint. "Save → re-run with old + new documents → put back" might reuse
  it, so nothing new has to be written for keeping state. Use it if it fits; tell me if there's a better way.
- Test it on a sample client: run with some documents, make a correction and a tick, add the rest, then check the
  correction and tick are still there and the totals match a run with all the documents from the start.
