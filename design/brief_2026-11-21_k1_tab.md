## Step 4 — K-1 Verification (former Interpreter, `templates\k1v\report.html`): links
1. **Bug — the K-1 jump links reload the app.** The list of K-1 names at the top (`#k1-0`, `#k1-1` …) should jump to
   that K-1's section on the same page. Today a click reloads 1040 Ultimate in the frame and asks for a new read.
   Cause: the page is drawn in a `srcdoc` frame, whose base address is the app's own address, so `#k1-3` becomes
   `<app address>#k1-3` and the frame loads the app. **Fix it once in `SHIM` (`web\index.html`):** a link whose
   address starts with `#` scrolls to that element inside the page and never navigates; the page's own click code runs
   first (the tabs view uses the same links to switch tabs). This fixes every `#` link on every page.
2. **Each K-1's name in its card header is a link that opens that K-1's PDF at that K-1's page**, in the document's own
   tab (already open → it moves to the page). The page number in the run is file-coded (2nd file = 1001+, 3rd = 2001+):
   the file is `run["files"][page // 1000]`, the page in it is `page % 1000`. Show the real page ("PDF page 3"), not 1003.
3. The rename: buttons, page title and headings say **K-1 Verification**.

## Step 5 — The K-1 tab (the main tab drives a second tab)
"Open K-1 Tab" on the Summary opens the K-1s page in **its own browser tab**. Everything in that tab (the K-1s page,
K-1 Verification, K-1 UT) is drawn by the **main tab's worker**: one Python, one set of documents, one load.
- One K-1 tab per client run: the tab is named (like the document tabs, `window.open("", name)`), so a second click
  brings the open tab back instead of opening another.
- Inside the K-1 tab, links, saves, downloads, forms and `sendBeacon` work exactly as in the main tab's frame — they go
  to the main tab's `u1040` (the same SHIM, pointing at the opener instead of `parent`).
- **Document links inside the K-1 tab** (K-1 PDFs list, K-1 name links) open the PDF tabs. Chrome only lets a click
  open a tab from the window that was clicked: open the tab in the K-1 tab's click, then fill it from the main tab's copy.
  Test that pop-ups aren't blocked.
- When the K-1 tab **adds to or removes from the Income Summary**, the main tab redraws the Summary (the K-1 box and
  totals change) — keep the scroll position.
- "← 1040 Ultimate (this client)" in the K-1 tab brings the main tab to the front; it doesn't load the Summary in the
  K-1 tab.
- **If the main tab is closed or reloaded**, the K-1 tab can't work any more. It must say so plainly ("The 1040 Ultimate
  tab was closed or reloaded — open the K-1 tab again from the Summary") instead of failing silently. Nothing saved is
  lost: the K-1 work file is written after each change, as today.
- Pop-ups blocked for the site: the same message as the document tabs, and the K-1s open inside the app as today.
